# バージョンと、前の店に戻る方法

## 決まり

- 区切りのいいところで、バージョンに番号をつける（`0.1.0`、`0.2.0`……）
- 番号は git のタグ（`v0.2.0` など）と、GitHub のリリースに残す
- 設定資料（`docs/`）もソースと同じリポジトリにあるので、タグ一つで「そのときの店」と「そのときの設定」がそろって残る
- 何が変わったかは [CHANGELOG.md](../CHANGELOG.md) に書く
- 番号は `package.json`、`src/version.js`、CHANGELOG の三か所をそろえる（スケッチ帳の下に版が出る）
- 開店前は `0.x`。開店したら `1.0.0`

番号の上げ方：

| 変わったもの | 例 | 上げる場所 |
|---|---|---|
| 景色や体験が大きく変わった | 店の構図を変えた、BGMが入った | 真ん中（0.**2**.0） |
| 小さな直し | 色の調整、ひとりごとの追加 | 右（0.2.**1**） |

## 一覧

- GitHub のリリース一覧：https://github.com/koki-hq/warpix-yukashi/releases
- タグの一覧：`git tag -n`

## 前の店を見る・戻る

いちばん簡単なのは、Claude に「0.1.0 の店を見せて」「0.1.0 に戻して」と頼むこと。

自分でやるとき：

```
git switch --detach v0.1.0   # 0.1.0 の店をのぞく（見るだけ）
npm run serve                # http://127.0.0.1:8080/ で開く
git switch main              # いまの店に帰ってくる
```

前の店からやり直したいとき（いまの店も消さずに残る）：

```
git switch -c 別の道 v0.1.0
```

GitHub の上で、そのときのファイルを見るだけなら：
`https://github.com/koki-hq/warpix-yukashi/tree/v0.1.0`
